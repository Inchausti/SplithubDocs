Introdução e aspectos gerais / Autenticação

Autenticação

O Splithub usa OAuth 2.0 no fluxo client credentials. Troque o par de credenciais da sua integração por um token de curta duração e envie-o no cabeçalho Authorization de todas as requisições. Cada credencial tem escopos: uma chamada fora do escopo concedido responde 403.

Nunca envie o token nem o client_secret na URL ou na query string, e nunca os registre em log nem os transmita por e-mail ou chamado de suporte. Use sempre HTTPS.

Passo 1: obter um token

Envie o grant_type e o par de credenciais. O endpoint aceita JSON e também application/x-www-form-urlencoded com credencial por HTTP Basic, para bibliotecas OAuth 2.0 padrão.

POST /public/oauth/token 
curl -X POST https://api.splithub.com.br/public/oauth/token \
  -H "Content-Type: application/json" \
  -d '{
    "grant_type": "client_credentials",
    "client_id": "your_client_id",
    "client_secret": "your_client_secret"
  }'
POST /public/oauth/token — formulário com HTTP Basic 
curl -X POST https://api.splithub.com.br/public/oauth/token \
  -u "your_client_id:your_client_secret" \
  -d "grant_type=client_credentials"

A resposta traz o token, a validade em segundos e os escopos concedidos:

Resposta 200 OK
{
  "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "token_type": "Bearer",
  "expires_in": 720,
  "scope": ["contracts:read", "contracts:write"]
}
CampoTipoDescrição
access_tokenstringToken a enviar no cabeçalho Authorization
token_typestringSempre "Bearer"
expires_innumberValidade em segundos. Use sempre o valor devolvido; não fixe a validade no código
scopearrayEscopos concedidos a esta credencial

Passo 2: usar o token nas chamadas de API

Inclua o token no cabeçalho Authorization de todas as requisições, no formato Bearer {access_token}.

Requisição autenticada 
curl https://api.splithub.com.br/v1/fornecedores \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIs..."

Validade e renovação

O token vale 12 minutos. Reutilize-o enquanto for válido e renove com cerca de 2 minutos de folga — pedir um token por requisição esgota o limite de emissão. Com token expirado, a resposta é 401: obtenha um token novo e repita a chamada.

Resposta 401 Unauthorized
{
  "error": "token_expired",
  "message": "Access token has expired. Generate a new token."
}

Escopos

Os escopos são concedidos na criação da credencial. Uma chamada a um recurso fora dos escopos concedidos responde 403 forbidden.

EscopoPermite
suppliers:readConsultar fornecedores
suppliers:writeCadastrar fornecedores e alterar cadastro e situação
supplier_representatives:readConsultar representantes fiscais
supplier_representatives:writeCadastrar e alterar representantes fiscais
contracts:readConsultar contratos
contracts:writeCriar contratos e alterar dados e situação
dfs:readConsultar documentos fiscais e lotes
dfs:writeEnviar, corrigir e remover documentos fiscais
apuracoes:readConsultar créditos e débitos de IBS e CBS
supplier_guias:readConsultar guias de recolhimento (RAD)
supplier_guias:payEnviar comprovante de pagamento de guia (RAD)
webhooks:readConsultar inscrições, o log de entrega e o log de eventos
webhooks:writeCriar e alterar inscrições, rotacionar o segredo e reenviar entregas
