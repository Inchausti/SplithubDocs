Garantia de crédito

Um Documento Fiscal (DF) de entrada gera crédito tributário de IBS/CBS para o comprador; um DF de saída gera débito para quem vende. Pela Lei Complementar 214/2025, a apuração do IBS/CBS é não cumulativa e opera por compensação "tributo contra tributo": o débito de uma saída é extinto abatendo-se os créditos já apropriados. O Splithub acompanha esse ciclo de vida por valor de cada DF e avisa seu sistema a cada mudança de status através de dois webhooks.

Diferente do ICMS, em que bastava o destaque do imposto na nota, o direito ao crédito de IBS/CBS depende do pagamento efetivo do tributo na própria NF de entrada. Na apuração da IBS/CBS, débitos e créditos são compensados de forma agregada por período; o Splithub modela esse ciclo por valor de cada DF para dar rastreabilidade a cada crédito e débito individualmente.

Ciclo de vida do crédito e do débito

Fluxo completo, por valor de cada DF:

1. O fornecedor emite uma NF de entrada para o comprador → nasce um crédito nao_apropriado.
2. O tributo dessa NF de entrada é pago → o crédito passa a apropriado.
3. O adquirente (o mesmo comprador, agora na ponta de venda) emite uma NF de saída → nasce um débito nao_extinto.
4. Essa NF de saída é abatida pelos créditos apropriados disponíveis (compensação tributo contra tributo) → o crédito utilizado nessa compensação passa a utilizado e o débito correspondente passa a extinto, simultaneamente.

TributoStatusQuando ocorre
Créditonao_apropriadoNF de entrada emitida pelo fornecedor; o tributo dessa NF ainda não foi pago
CréditoapropriadoO tributo da NF de entrada foi pago
CréditoutilizadoO crédito apropriado foi usado para abater (compensar) o débito de uma NF de saída
Débitonao_extintoNF de saída emitida pelo adquirente; ainda não foi abatida por créditos
DébitoextintoA NF de saída foi abatida pelos créditos apropriados disponíveis (compensação tributo contra tributo)

Webhook event: mudança de status do crédito

Disparado sempre que o crédito tributário referente a um DF de entrada muda de status (nao_apropriado → apropriado → utilizado). No exemplo abaixo, o crédito acabou de ser utilizado para compensar o débito de uma NF de saída — por isso o evento traz também a chaveDfeDebitoCompensado.

POST {sua_url_de_webhook} 
{
  "event": "credito.status_alterado",
  "createdAt": "2026-07-29T15:00:00.000Z",
  "data": {
    "chaveDfe": "35260714200166000187550010000012341234567890",
    "tipoTributo": "cbs",
    "valorCredito": 9.00,
    "statusAnterior": "apropriado",
    "statusAtual": "utilizado",
    "motivoAlteracao": "compensacao_debito_saida",
    "chaveDfeDebitoCompensado": "35260714200166000187550010000098769876543210"
  }
}

Seu endpoint deve responder 200 OK para confirmar o recebimento. Sem essa confirmação, o Splithub reenvia o evento.

data.chaveDfestringChave de acesso do DF de entrada que originou o crédito

Webhook event: mudança de status do débito

Disparado sempre que o débito tributário referente a um DF de saída muda de status (nao_extinto → extinto). A extinção ocorre quando a NF de saída é abatida pelos créditos apropriados disponíveis — por isso o evento traz também creditosUtilizados, com a chave e o valor de cada crédito usado na compensação.

POST {sua_url_de_webhook} 
{
  "event": "debito.status_alterado",
  "createdAt": "2026-07-29T15:00:00.000Z",
  "data": {
    "chaveDfe": "35260714200166000187550010000098769876543210",
    "tipoTributo": "ibs",
    "valorDebito": 1.00,
    "statusAnterior": "nao_extinto",
    "statusAtual": "extinto",
    "modalidadeExtincao": "compensacao_credito_entrada",
    "creditosUtilizados": [
      { "chaveDfe": "35260714200166000187550010000012341234567890", "valorUtilizado": 1.00 }
    ]
  }
}

Seu endpoint deve responder 200 OK para confirmar o recebimento. Sem essa confirmação, o Splithub reenvia o evento.
