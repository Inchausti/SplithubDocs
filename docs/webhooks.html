Introdução e aspectos gerais / Webhooks

Webhooks

O Splithub utiliza webhooks para notificar sua aplicação em tempo real quando eventos importantes ocorrem no sistema. Em vez de fazer polling (perguntar repetidamente), sua aplicação recebe notificações HTTP POST automáticas quando eventos como "DARF recebido", "crédito alterado" ou "comprovante enviado" acontecem. Isso permite que você mantenha seus sistemas sincronizados com baixa latência e sem sobrecarga desnecessária.

Conceitos e Configuração

Para começar a receber webhooks, configure uma URL pública, em HTTPS, na sua conta Splithub. O Splithub envia cada evento para essa URL por POST, com o evento no corpo da requisição em JSON.

Envelope do evento

Todos os eventos têm o mesmo envelope; o que muda é o conteúdo de data.

Envelope
{
  "id": "evt_9f2a3c",
  "type": "rad.darf_recebida",
  "occurred_at": "2026-09-25T14:03:11Z",
  "data": { /* conteúdo do evento */ }
}
CampoTipoDescrição
idstringIdentificador do evento e chave de deduplicação. Reentregas repetem o mesmo valor
typestringTipo do evento. Faz parte do contrato: um tipo não muda de formato — mudança de formato gera tipo novo
occurred_attimestampMomento em que o fato ocorreu, não o do envio. Os dois divergem quando há retentativa
dataobjectConteúdo do evento, descrito na página de cada recurso

Entrega e retentativas

AspectoRegra
SucessoQualquer resposta 2xx
Tempo limite30 segundos. Processe de forma assíncrona: enfileire o evento e responda logo
RetentativasAté 10, com a espera dobrando a partir de 1 minuto — a última por volta de 17 horas depois — e dispersão aleatória

Segurança: Verificação de Assinatura

Cada envio traz dois cabeçalhos: X-Splithub-Timestamp, com o momento do envio em segundos (epoch), e X-Splithub-Signature, com v1= seguido do HMAC-SHA256 em hexadecimal. A assinatura cobre o carimbo de tempo e o corpo: timestamp + "." + corpo bruto. Incluir o carimbo impede que um evento capturado seja reenviado depois por terceiros.

Verificação em três passos:

  1. Recuse o evento se o carimbo de tempo estiver fora de uma janela de 5 minutos do seu relógio
  2. Calcule HMAC-SHA256(secret, timestamp + "." + raw_body) e compare com o valor depois de v1=, em comparação de tempo constante
  3. Descarte o evento se o id já foi processado — guarde os ids por pelo menos 24 horas
Exemplo: Validar assinatura em JavaScript/Node.js 
const crypto = require("crypto");
const express = require("express");

const app = express();
const WEBHOOK_SECRET = process.env.WEBHOOK_SECRET;
const JANELA_SEGUNDOS = 5 * 60;

// Middleware para capturar o corpo bruto
app.use(express.raw({ type: "application/json" }));

app.post("/webhooks/splithub", async (req, res) => {
  const timestamp = req.headers["x-splithub-timestamp"];
  const assinatura = (req.headers["x-splithub-signature"] || "").replace(/^v1=/, "");
  const rawBody = req.body; // Buffer com o corpo bruto

  // 1. Janela de tempo
  const agora = Math.floor(Date.now() / 1000);
  if (!timestamp || Math.abs(agora - Number(timestamp)) > JANELA_SEGUNDOS) {
    return res.status(401).json({ error: "Carimbo fora da janela" });
  }

  // 2. HMAC sobre timestamp + "." + corpo bruto, em tempo constante
  const esperada = crypto
    .createHmac("sha256", WEBHOOK_SECRET)
    .update(timestamp + "." + rawBody)
    .digest("hex");
  const a = Buffer.from(esperada), b = Buffer.from(assinatura);
  if (a.length !== b.length || !crypto.timingSafeEqual(a, b)) {
    return res.status(401).json({ error: "Assinatura inválida" });
  }

  // 3. Deduplicação pelo id do evento
  const evento = JSON.parse(rawBody);
  if (await jaProcessado(evento.id)) {
    return res.json({ status: "duplicate" });
  }

  if (evento.type === "rad.darf_recebida") {
    await enfileirar(processarDarf, evento);
  } else if (evento.type === "rad.proof_received") {
    await enfileirar(processarComprovante, evento);
  }

  return res.json({ status: "received" });
});

CabeçalhosX-Splithub-Timestamp (epoch em segundos) e X-Splithub-Signature (v1= + HMAC em hexadecimal)

Melhores Práticas

  • Deduplicação: Use o campo id do envelope para deduplicar (em cache Redis ou banco de dados) e evitar processar o mesmo evento duas vezes
  • Processamento Assíncrono: Não faça operações pesadas no handler do webhook; enfileire o evento e retorne 200 OK imediatamente
  • Logging: Registre todos os webhooks recebidos (timestamp, ID, tipo de evento, status) para auditoria
  • Monitoramento: Crie alertas para taxa de erro > 5% ou latência > 10s
  • Validação de Dados: Mesmo após validar assinatura, valide os dados do evento (tipos, campos obrigatórios)
  • Respeite Retry-After: Se enviar status 429 (too many requests), inclua header Retry-After
