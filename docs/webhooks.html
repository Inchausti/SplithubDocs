Webhooks

O Splithub utiliza webhooks para notificar sua aplicação em tempo real quando eventos importantes ocorrem no sistema. Em vez de fazer polling (perguntar repetidamente), sua aplicação recebe notificações HTTP POST automáticas quando eventos como "DARF recebido", "crédito alterado" ou "comprovante enviado" acontecem. Isso permite que você mantenha seus sistemas sincronizados com baixa latência e sem sobrecarga desnecessária.

Conceitos e Configuração

Para começar a receber webhooks, configure uma URL pública em sua conta Splithub onde seu servidor possa receber requisições POST. O Splithub envia eventos para essa URL com todas as informações do evento no corpo (body) da requisição em formato JSON.

Seu endpoint de webhook deve responder com status 200 OK em até 30 segundos. Sem confirmação, o Splithub faz retry automático com backoff exponencial (até 10 tentativas ao longo de ~18 horas). Processe o evento de forma assíncrona se a lógica for complexa.

Segurança: Verificação de Assinatura

Todo webhook enviado pelo Splithub inclui um cabeçalho X-Splithub-Signature contendo uma assinatura HMAC-SHA256 do corpo da requisição. Valide essa assinatura para garantir que o webhook veio realmente do Splithub e não foi alterado em trânsito.

Processo de verificação:

  1. Recupere o secret da sua conta (configurado no portal Splithub)
  2. Pegue o corpo bruto da requisição (raw body, não parseado)
  3. Calcule HMAC-SHA256(secret, raw_body)
  4. Compare o resultado com o valor do header X-Splithub-Signature usando comparação timing-safe
  5. Rejeite se as assinaturas não forem idênticas
Exemplo: Validar assinatura em Python 
import hmac
import hashlib
from flask import Flask, request

app = Flask(__name__)
WEBHOOK_SECRET = "seu_secret_aqui"  # Guarde em variável de ambiente

@app.route("/webhooks/splithub", methods=["POST"])
def handle_webhook():
    signature = request.headers.get("X-Splithub-Signature")
    body = request.get_data()  # Raw body é crítico

    # Calcular assinatura esperada
    expected_signature = hmac.new(
        WEBHOOK_SECRET.encode(),
        body,
        hashlib.sha256
    ).hexdigest()

    # Comparação timing-safe
    if not hmac.compare_digest(expected_signature, signature):
        return {"error": "Assinatura inválida"}, 401

    # Processar webhook
    data = request.json
    event_type = data.get("event")

    if event_type == "rad.darf_recebida":
        processar_darf(data)
    elif event_type == "rad.comprovante_enviado":
        processar_comprovante(data)

    return {"status": "received"}, 200
Exemplo: Validar assinatura em JavaScript/Node.js 
const crypto = require("crypto");
const express = require("express");

const app = express();
const WEBHOOK_SECRET = process.env.WEBHOOK_SECRET;

// Middleware para capturar raw body
app.use(express.raw({ type: "application/json" }));

app.post("/webhooks/splithub", (req, res) => {
  const signature = req.headers["x-splithub-signature"];
  const rawBody = req.body; // Buffer com o corpo bruto

  // Calcular assinatura esperada
  const expectedSignature = crypto
    .createHmac("sha256", WEBHOOK_SECRET)
    .update(rawBody)
    .digest("hex");

  // Comparação timing-safe
  if (!crypto.timingSafeEqual(
    Buffer.from(expectedSignature),
    Buffer.from(signature)
  )) {
    return res.status(401).json({ error: "Assinatura inválida" });
  }

  // Processar webhook
  const data = JSON.parse(rawBody);
  const eventType = data.event;

  if (eventType === "rad.darf_recebida") {
    processarDarf(data);
  } else if (eventType === "rad.comprovante_enviado") {
    processarComprovante(data);
  }

  return res.json({ status: "received" });
});

Melhores Práticas

  • Deduplicação: Use o campo id do evento para deduplicar (em cache Redis ou banco de dados) e evitar processar o mesmo evento duas vezes
  • Processamento Assíncrono: Não faça operações pesadas no handler do webhook; enfileire o evento e retorne 200 OK imediatamente
  • Logging: Registre todos os webhooks recebidos (timestamp, ID, tipo de evento, status) para auditoria
  • Monitoramento: Crie alertas para taxa de erro > 5% ou latência > 10s
  • Validação de Dados: Mesmo após validar assinatura, valide os dados do evento (tipos, campos obrigatórios)
  • Respeite Retry-After: Se enviar status 429 (too many requests), inclua header Retry-After
