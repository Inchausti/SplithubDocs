Introdução e aspectos gerais / Autenticação

Autenticação

O Splithub utiliza autenticação JSON Web Token (JWT). Envie suas credenciais de cliente para obter um access token e utilize-o no cabeçalho Authorization de todas as requisições subsequentes.

Nunca envie o access token na URL ou query string. Ele deve ser transmitido apenas no cabeçalho Authorization, sempre via HTTPS.

Passo 1: obter um token

Envie suas credenciais como JSON para o endpoint de login. A resposta traz um access_token assinado e o tempo de expiração em segundos.

POST /v1/auth/login 
curl -X POST https://api.splithub.com.br/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{
    "client_id": "your_client_id",
    "client_secret": "your_client_secret"
  }'

A resposta contém o JWT access token e o tempo de expiração:

Resposta 200 OK
{
  "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "expires_in": 3600,
  "token_type": "Bearer"
}

Passo 2: usar o token nas chamadas de API

Inclua o access token no cabeçalho Authorization de todas as requisições usando o formato Bearer {access_token}.

Requisição autenticada 
curl https://api.splithub.com.br/v1/fornecedores \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIs..."

Expiração do token

O access token expira após o tempo especificado em expires_in (em segundos). Requisições feitas com um token expirado recebem 401 Unauthorized; neste caso, repita o Passo 1 para obter um novo access token.

Resposta 401 Unauthorized
{
  "error": "token_expired",
  "message": "Access token has expired. Generate a new token."
}
