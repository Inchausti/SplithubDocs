Recursos / Ingestão DFs

Ingestão DFs

O Splithub permite receber (ingerir) Documentos Fiscais para que os tributos de cada documento sejam identificados e processados automaticamente pelas regras de separação. Com a Reforma Tributária, o Fisco passa a trabalhar com 14 tipos de DFs (Documentos Fiscais Eletrônicos), cada um cobrindo uma categoria diferente de operação.

Estes são os 14 tipos de DF-e previstos, com o modelo oficial e o tipo de operação que cada um documenta. Informe o tipo correto no campo type ao criar um documento.

Documentos Fiscais para Apuração Assistida

A partir de 1º de janeiro de 2026, todos os documentos fiscais incluem obrigatoriamente campos de IBS (Imposto sobre Bens e Serviços) e CBS (Contribuição sobre Bens e Serviços) que alimentam a apuração assistida da Receita Federal e CGIBS. O Fisco consolida automaticamente débitos/créditos e apresenta a apuração assistida (similar a uma "declaração pré-preenchida", com créditos e débitos). Se o contribuinte não se manifestar, ocorre confissão tácita.

Todos os 14 tipos suportam apuração assistida, mas apenas estes 10 foram explicitamente mencionados nas normas oficiais: NF-e, NFC-e, NFCom, NF3-e, NFS-e, CT-e, NFAg, NFGás, MDF-e e BP-e.

Campos obrigatórios (Grupo UB): cst_ibs, cst_cbs, cclasstr (conforme Lei Complementar 214/2025 + Nota Técnica 2025.002 v.1.35)

Por esta chamada aceitamos um JSON estruturado equivalente aos grupos da NF-e 4.0 e outros leiautes DF-e (NFCom, CT-e, BP-e, etc.) atualizados pela Nota Técnica 2025.002. A API adapta automaticamente conforme o type informado. Obrigatório: Grupo de IBS/CBS (CST e cClassTrib), valores de base e tributação. Sem esses dados, a partir de 03/08/2026 a nota é rejeitada pela SEFAZ. O processamento é assíncrono; use o endpoint de consulta para acompanhar o status.

O campo contract_id referencia o contrato entre cliente (destinatário) e fornecedor (emitente) no módulo de Contratos. Quando informado, permite rastrear qual contrato gerou a obrigação fiscal. Use o identificador retornado na criação do contrato (ex: ctr_5f8a2d).

Criar um documento fiscal

Envie o documento como JSON estruturado — o XML assinado e o ZIP de XMLs entram pelo envio de arquivo. A API adapta-se automaticamente conforme o type informado (NF-e, NFCom, CT-e, BP-e, etc.). Independentemente do tipo, inclua: identification (identificação), emission (emitente), destination (destinatário), items (itens ou serviços), e total (totalizadores). O Grupo de IBS/CBS (items[].tax.ibs_cbs) é obrigatório em todos os tipos; para NFCom, CT-e OS e outros, inclua também campos específicos (como competence_date em NFCom). A API retorna um identificador para acompanhar o processamento.

Enviar arquivo

Para carga em volume e para o XML assinado. Você envia o arquivo, vê o que entra e o que não entra — com o motivo de cada recusa — e só então confirma. Nenhum documento é registrado antes da confirmação. Cada documento lido vira o corpo de POST /v1/fiscal-documents e passa pelas mesmas verificações.

Nesta versão o arquivo é lido no nível do documento — identificação, partes, contrato e totais. Os itens não são lidos: o CSV tem uma linha por documento, e no JSON, no XML e no ZIP os itens são ignorados.

PassoChamadaO que faz
1POST /v1/uploadsRecebe o arquivo e devolve o id. Não lê o conteúdo
2POST /v1/ingestionsLê, verifica e devolve a prévia: o que entra, o que não entra e por quê
3POST /v1/ingestions/{id}/confirmImporta só os documentos importáveis. Responde 202
4GET /v1/ingestions/{id}Acompanha até confirmed ou failed

1. Enviar o arquivo

Em multipart/form-data, com o arquivo e a finalidade. O mesmo arquivo enviado de novo em 24 horas traz em duplicate_of o envio anterior.

A duplicidade é verificada de novo na confirmação. Entre a prévia e a confirmação o mesmo documento pode chegar pela API; ele sai dos importáveis com access_key_already_registered, e o resumo final mostra quantos mudaram em rechecked_at_confirmation.

4. Acompanhar

Consulte GET /v1/ingestions/{id} com espera crescente — 10 segundos, dobrando até 2 minutos — ou assine o evento ingestion.completed. Concluída a importação, GET /v1/ingestions/{id}/documents devolve o document_id de cada chave. Para desistir antes de confirmar, POST /v1/ingestions/{id}/cancel.

Atualizar um documento fiscal

Corrija campos de um documento antes de ele ser concluído — por exemplo, dados do destinatário ou itens registrados com erro.

Só é possível atualizar um documento com status pending ou error. Documentos com status completed são imutáveis, refletindo a legislação fiscal.

PATCH /v1/fiscal-documents/{id} 
curl -X PATCH https://api.splithub.com.br/v1/fiscal-documents/df_8f3a1c2b \
  -H "Authorization: Bearer {token}" \
  -H "Idempotency-Key: df_8f3a1c2b-correcao-01" \
  -H "Content-Type: application/json" \
  -d '{
    "destination": {
      "cnpj_cpf": "98765432000188",
      "name": "Cliente Exemplo LTDA - Matriz"
    }
  }'
Resposta 200 OK
{
  "id": "df_8f3a1c2b",
  "status": "pending",
  "destination": { "cnpj_cpf": "98765432000188", "name": "Cliente Exemplo LTDA - Matriz" }
}

Remover um documento fiscal

Remove o registro de ingestão da Splithub — não é o mesmo que cancelar o documento junto ao Fisco, que continua sendo feito no seu sistema emissor.

DELETE /v1/fiscal-documents/{id} 
curl -X DELETE https://api.splithub.com.br/v1/fiscal-documents/df_8f3a1c2b \
  -H "Authorization: Bearer {token}"
Resposta 204 No Content
