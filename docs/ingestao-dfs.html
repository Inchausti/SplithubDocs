Ingestão DFs

O Splithub permite enviar (ingerir) Documentos Fiscais para que os tributos de cada documento sejam identificados e processados automaticamente pelas regras de separação. Com a Reforma Tributária, o Fisco passa a trabalhar com 14 tipos de DFs (Documentos Fiscais Eletrônicos), cada um cobrindo uma categoria diferente de operação.

Estes são os 14 tipos de DF-e previstos, com o modelo oficial e o tipo de operação que cada um documenta. Informe o tipo correto no campo type ao criar um documento.

Documentos Fiscais para Apuração Assistida

A partir de 1º de janeiro de 2026, todos os documentos fiscais incluem obrigatoriamente campos de IBS (Imposto sobre Bens e Serviços) e CBS (Contribuição sobre Bens e Serviços) que alimentam a apuração assistida da Receita Federal e CGIBS. O Fisco consolida automaticamente débitos/créditos e apresenta uma declaração pré-preenchida. Se o contribuinte não se manifestar, ocorre confissão tácita.

Todos os 14 tipos suportam apuração assistida, mas apenas estes 10 foram explicitamente mencionados nas normas oficiais: NF-e, NFC-e, NFCom, NF3-e, NFS-e, CT-e, NFAg, NFGás, MDF-e e BP-e.

Campos obrigatórios (Grupo UB): cst_ibs, cst_cbs, cclasstr (conforme Lei Complementar 214/2025 + Nota Técnica 2025.002 v.1.35)

Aceitamos o XML assinado do documento fiscal ou um JSON estruturado equivalente aos grupos da NF-e 4.0 e outros leiautes DF-e (NFCom, CT-e, BP-e, etc.) atualizados pela Nota Técnica 2025.002. A API adapta automaticamente conforme o type informado. Obrigatório: Grupo de IBS/CBS (CST e cClassTrib), valores de base e tributação. Sem esses dados, a partir de 03/08/2026 a nota é rejeitada pela SEFAZ. O processamento é assíncrono; use o endpoint de consulta para acompanhar o status.

O campo contract_id referencia o contrato entre cliente (destinatário) e fornecedor (emitente) no módulo de Contratos. Quando informado, permite rastrear qual contrato gerou a obrigação fiscal. Use o identificador retornado na criação do contrato (ex: ctr_5f8a2d).

Criar um documento fiscal

Envie o XML do documento assinado em base64 ou um JSON estruturado. A API adapta-se automaticamente conforme o type informado (NF-e, NFCom, CT-e, BP-e, etc.). Independentemente do tipo, inclua: identification (identificação), emission (emitente), destination (destinatário), items (itens ou serviços), e total (totalizadores). O Grupo de IBS/CBS (items[].tax.ibs_cbs) é obrigatório em todos os tipos; para NFCom, CT-e OS e outros, inclua também campos específicos (como competence_date em NFCom). A API retorna um identificador para acompanhar o processamento.

POST /v1/documentos-fiscais 
curl -X POST https://api.splithub.com.br/v1/documentos-fiscais \
  -H "Authorization: Bearer {token}" \
  -H "Content-Type: application/json" \
  -d '{
    "type": "nfe",                    // REQUIRED
    "model": "55",                    // REQUIRED
    "access_key": "3526071420016...", // REQUIRED - 44 dígitos
    "contract_id": "ctr_5f8a2d",      // OPTIONAL
    "identification": {               // REQUIRED
      "number": "123456",             // REQUIRED
      "series": "1",                  // REQUIRED
      "emission_date": "2026-07-29T10:00:00-03:00" // REQUIRED - ISO 8601
    },
    "emission": {                     // REQUIRED
      "cnpj": "14200166000187",       // REQUIRED
      "legal_name": "Fornecedor...",  // REQUIRED
      "state": "SP"                   // REQUIRED
    },
    "destination": {                  // REQUIRED
      "cnpj_cpf": "98765432000188",   // REQUIRED
      "name": "Cliente...",           // REQUIRED
      "state": "RJ"                   // REQUIRED
    },
    "items": [                        // REQUIRED - array
      {
        "code": "SKU-1029",           // REQUIRED
        "description": "Notebook...", // REQUIRED
        "ncm": "84713012",            // OPTIONAL - para NF-e
        "cfop": "5102",               // REQUIRED
        "quantity": 2,                // REQUIRED
        "unit_price": 3200.00,        // REQUIRED
        "total_value": 6400.00,       // REQUIRED
        "tax": {                      // REQUIRED
          "ibs_cbs": {                // REQUIRED - Lei Complementar 214/2025
            "cst": "000",             // REQUIRED
            "c_class_trib": "000001", // REQUIRED
            "v_bc": 6400.00,          // REQUIRED
            "g_ibs_uf": { "p_ibs_uf": 0.05, "v_ibs_uf": 3.20 }, // REQUIRED

Durante 2026, v_tot_ibs e v_tot_cbs não compõem o total_note_value — eles são informados à parte no Grupo W03, refletindo a fase de testes com cobrança simbólica (0,9% CBS + 0,1% IBS, dividido entre g_ibs_uf e g_ibs_mun). Os campos são flexíveis: use ncm para NF-e ou service_type para NFCom conforme necessário.

Listar documentos fiscais

Liste os documentos ingeridos, com filtros opcionais por type e status.

GET /v1/documentos-fiscais 
curl "https://api.splithub.com.br/v1/documentos-fiscais?tipo=nfe&status=concluido" \
  -H "Authorization: Bearer {token}"
Resposta 200 OK
{
  "data": [

Atualizar um documento fiscal

Corrija campos de um documento antes de ele ser concluído — por exemplo, dados do destinatário ou itens registrados com erro.

Só é possível atualizar um documento com status pending ou error. Documentos com status completed são imutáveis, refletindo a legislação fiscal.

PATCH /v1/documentos-fiscais/{id} 
curl -X PATCH https://api.splithub.com.br/v1/documentos-fiscais/df_8f3a1c2b \
  -H "Authorization: Bearer {token}" \
  -H "Content-Type: application/json" \
  -d '{
    "destination": {
      "cnpj_cpf": "98765432000188",
      "name": "Cliente Exemplo LTDA - Matriz"
    }
  }'
Resposta 200 OK
{
  "id": "df_8f3a1c2b",
  "status": "pending",
  "destination": { "cnpj_cpf": "98765432000188", "name": "Cliente Exemplo LTDA - Matriz" }
}

Remover um documento fiscal

Remove o registro de ingestão da Splithub — não é o mesmo que cancelar o documento junto ao Fisco, que continua sendo feito no seu sistema emissor.

DELETE /v1/documentos-fiscais/{id} 
curl -X DELETE https://api.splithub.com.br/v1/documentos-fiscais/df_8f3a1c2b \
  -H "Authorization: Bearer {token}"
Resposta 204 No Content
