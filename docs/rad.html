Recursos / RAD

RAD (Recolhimento pelo Adquirente)

RAD é o mecanismo em que o adquirente da transação — a empresa que atua como compradora na operação e é contribuinte do IBS e da CBS no regime regular — retém e recolhe a parcela de tributos diretamente à Receita Federal e ao Comitê Gestor do IBS, repassando ao fornecedor – a empresa que atua como vendedora na operação – apenas o valor líquido. O Splithub recebe as guias de pagamento da CBS e do IBS geradas nesse fluxo e o comprovante dos pagamentos realizados, para manter a conciliação completa.

Os dois modos de pagamento da guia

Quem paga a guia RAD é sempre o adquirente. O que muda é quem executa o pagamento — e isso é escolhido na implantação, para cada cliente:

ModoComo funcionaO que seu sistema faz
Instrução pelo SplithubO Splithub instrui o pagamento da guia em nome do adquirenteRecebe rad.darf_received para os lançamentos e rad.proof_received quando o pagamento é feito. Não envia comprovante
Pagamento pelo ERPO ERP do adquirente paga a guia e devolve o comprovante ao SplithubRecebe rad.darf_received, paga a guia e envia o comprovante por POST /v1/rad/proofs. Recebe rad.proof_received quando o comprovante é processado

O contrato da instrução de pagamento pelo Splithub será publicado neste changelog. Até lá, a integração completa está descrita para o modo de pagamento pelo ERP.

Webhook event: guia de DARF recebida

Assim que uma guia de DARF (CBS ou IBS) é gerada no fluxo de RAD, o Splithub dispara este evento por POST para a URL de webhook configurada na sua conta — você não chama nenhum endpoint do Splithub para isso, apenas recebe o evento. O objetivo é que seu ERP receba todas as informações necessárias para capturar as guias de pagamento (CBS e IBS), realizar os lançamentos contábeis para o documento fiscal relacionado, bem como acompanhar as alterações de status de crédito associadas à operação.

Nesta versão só é suportada a payment_method RAD (Recolhimento pelo Adquirente); PRESP (Pagamento pelo Responsável) fica reservado para uma versão futura. Como cada evento se refere a um único tributo (CBS ou IBS), incluímos o campo darf_type para identificar qual guia foi recebida — você receberá dois eventos separados, um para cada tributo, contendo todas as informações necessárias para capturar e lançar cada guia no seu ERP.

Este webhook é disparado uma única vez por lote de DFs, consolidando todas as guias de ambos os tributos (CBS e IBS). O campo summary agrupa os totais de retenção para facilitar auditoria e reconciliação contábil no seu ERP.

Consultar guias

Os eventos de guia recebida avisam cada guia gerada. A consulta é o caminho de reconciliação: use-a para conferir quais guias estão a vencer ou atrasadas, ou para recuperar uma guia cujo evento se perdeu. Retorna uma linha por guia, e não por documento: a quitação acontece por guia, e cada tributo tem a sua. O id da guia é o darf_id usado no envio do comprovante.

curl "https://api.splithub.com.br/v1/rad/guides?period=2026-07&status=upcoming&tax_type=cbs&limit=50" \
  -H "Authorization: Bearer {token}"

Enviar o comprovante de pagamento

No modo de pagamento pelo ERP, depois de pagar a guia por PIX ou boleto, envie o comprovante ao Splithub para conciliar a retenção com o pagamento efetivamente realizado. Utilize payment_type para indicar o método e inclua os campos específicos: pix (com end_to_end_id, txid, pix_key, amount, paid_at) ou bank_slip (com our_number, barcode, amount_paid, paid_at).

POST /v1/rad/proofs — Exemplo PIX 
curl -X POST https://api.splithub.com.br/v1/rad/proofs \
  -H "Authorization: Bearer {token}" \
  -H "Idempotency-Key: comp-darf_9f21ab" \
  -H "Content-Type: application/json" \
  -d '{
    "darf_id": "darf_9f21ab",                   
    "payment_type": "pix",                   
    "pix": {                                    // REQUIRED (when payment_type=pix)
      "end_to_end_id": "E14200166...",        
      "txid": "cbs_df_8f3a1c2b",              
      "pix_key": "14200166000187",          
      "amount": "57.60",                       
      "paid_at": "2026-07-29T12:00:00.000Z", // REQUIRED - ISO 8601
      "description": "Pagamento DARF CBS..."     
    }
  }'
POST /v1/rad/proofs — Exemplo boleto 
curl -X POST https://api.splithub.com.br/v1/rad/proofs \
  -H "Authorization: Bearer {token}" \

Webhook event: recepção comprovante

Avisa que o pagamento de uma guia foi registrado. No modo de instrução pelo Splithub, sai quando o pagamento instruído em nome do adquirente é feito; no modo de pagamento pelo ERP, quando o comprovante enviado é processado. Quem recolhe é sempre o adquirente — o Splithub, quando instrui o pagamento, age em nome dele.

O campo status indica o resultado da transação: success (pagamento realizado com sucesso), pending (processamento em andamento) ou failed (falha na transação).
