RAD (Recolhimento pelo Adquirente)

RAD é o mecanismo em que o adquirente da transação — a instituição de pagamento — recolhe e retém a parcela de tributos diretamente na liquidação, repassando ao lojista apenas o valor líquido. O Splithub recebe a guia de DARF gerada nesse fluxo e o comprovante do pagamento realizado, para manter a conciliação completa.

O RAD está relacionado ao split payment previsto na Reforma Tributária: parte do valor da transação pode deixar de transitar pela conta do lojista, sendo recolhida automaticamente pelo adquirente.

Webhook event: guia de DARF recebida

Assim que uma guia de DARF (CBS ou IBS) é gerada no fluxo de RAD, o Splithub dispara este evento por POST para a URL de webhook configurada na sua conta — você não chama nenhum endpoint do Splithub para isso, apenas recebe o evento.

Nesta versão só é suportada a payment_method RAD (Recolhimento pelo Adquirente); PRESP (Pagamento pelo Responsável) fica reservado para uma versão futura. Como cada evento se refere a um único tributo, incluímos o campo darf_type (ibs ou cbs) para identificar qual guia foi recebida.

POST {sua_url_de_webhook} 
{
  "event": "rad.darf_recebida",
  "created_at": "2026-07-29T12:00:00.000Z",
  "data": {
    "dfe_key": "35260714200166000187550010000012341234567890",
    "darf_type": "cbs",
    "return_code": "DARF_GERADO",
    "pix_key": "34028316000103",
    "barcode": "858100000012345678901234567890123456789012",
    "darf_pdf_link": "https://sistema.rfb.gov.br/darf/df_8f3a1c2b.pdf",
    "darf_principal_value": 57.60,
    "darf_penalty_value": 0.00,
    "darf_interest_value": 0.00,
    "darf_total_value": 57.60
  }
}

Seu endpoint deve responder 200 OK para confirmar o recebimento. Sem essa confirmação, o Splithub reenvia o evento.

Submit payment proof

Após pagar um DARF via PIX ou Boleto, envie o comprovante ao Splithub para conciliar a retenção com o pagamento efetivamente realizado. Utilize tipo_pagamento para indicar o método e inclua os campos específicos: pix (com end_to_end_id, txid, chave_pix, valor, timestamp) ou boleto (com nosso_numero, codigo_barras, valor_pago, data_pagamento).

POST /v1/rad/proofs — Exemplo PIX 
curl -X POST https://api.splithub.com.br/v1/rad/proofs \
  -H "Authorization: Bearer {token}" \
  -H "Content-Type: application/json" \
  -d '{
    "darf_id": "darf_9f21ab",                   
    "tipo_pagamento": "pix",                   
    "pix": {                                    // REQUIRED (when tipo_pagamento=pix)
      "end_to_end_id": "E14200166...",        
      "txid": "cbs_df_8f3a1c2b",              
      "chave_pix": "14200166000187",          
      "valor": "57.60",                       
      "timestamp": "2026-07-29T12:00:00.000Z", // REQUIRED - ISO 8601
      "descricao": "Pagamento DARF CBS..."     
    }
  }'
POST /v1/rad/proofs — Exemplo Boleto 
curl -X POST https://api.splithub.com.br/v1/rad/proofs \
  -H "Authorization: Bearer {token}" \
  -H "Content-Type: application/json" \
  -d '{
    "darf_id": "darf_8e32kc",                  
    "tipo_pagamento": "boleto",                
    "boleto": {                                 // REQUIRED (when tipo_pagamento=boleto)
      "nosso_numero": "12345678",             
      "codigo_barras": "00190123456...",       // REQUIRED - 44 dígitos
      "linha_digitavel": "00190.12345...",     // REQUIRED - 48 dígitos
      "banco": "001",                          // REQUIRED - código banco
      "agencia": "1234",                      
      "conta": "123456",                      
      "valor_pago": "125.40",                 
      "data_pagamento": "2026-07-31T14:30...", // REQUIRED - ISO 8601
      "descricao": "Pagamento DARF IBS..."     
    }
  }'

Webhook event: recepção comprovante

Quando o Splithub realiza o pagamento de uma guia de DARF via PIX, o sistema dispara este webhook para sua URL configurada, informando que o pagamento foi realizado e enviando o comprovante da transação. Este webhook notifica que o Splithub assumiu e liquidou a obrigação tributária em nome do lojista.

Este webhook indica que o Splithub liquidou o DARF de forma automática via PIX. O campo status indica o resultado da transação: success (pagamento realizado com sucesso), pending (processamento em andamento) ou failed (falha na transação).
